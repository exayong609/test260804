## P95 版本实测

任务：`task_7c55d9ec-db20-4bd4-bfba-5943aeaab7a0`

Trace：`trace_97f818a9-d6e4-4c80-bf98-806026e738aa`

| 指标 | 真实结果 | 结论 |
|---|---:|---|
| 上传接口 | 1,403ms | 未通过 1 秒硬指标 |
| UI 稳定观察 | 约 19.2s | 仍未开始处理 |
| 最长观察 | 46.2s | 仍为 pending |
| 批次 / 已处理 | 0/10；0/10,000 | 全链路失败 |
| Trace | 仅 `ImportTaskCreated` | 文件持久化未完成 |
| 重复上传 | 5,669ms | 错误返回同一个不可用 pending 任务 |
| 监控 | 吞吐、分位、错误分布均为 0 | 无可验收数据 |

该分支在 Vercel Serverless 中依赖请求结束后的延迟文件持久化，函数结束后工作没有可靠完成；重复检测又把未持久化文件的 pending 任务当成可复用结果。该问题与数据库容量无关，fresh run 可稳定复现。

## 结论

`fix/main-exam-hardening` 的任务初始化、文件持久化、Outbox 激活、批次处理、幂等、Trace、监控和降级形成完整可验收链路。`fix/upload-p95-observability` 虽有部分 UI 和监控代码，但 fresh run 无法完成文件持久化，且上传超过 1 秒，触发最高 50 分封顶条件，不应作为提交版本。
